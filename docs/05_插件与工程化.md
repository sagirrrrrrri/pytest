## 5.1 配置文件：pytest.ini

pytest 会自动向上查找配置文件（`pytest.ini` 优先于 `pyproject.toml` 的 `[tool.pytest.ini_options]`）。

```ini
# pytest.ini（放在项目根目录）
[pytest]
# 测试文件/目录规则
testpaths = tests
python_files = test_*.py *_test.py
python_classes = Test*
python_functions = test_*

# 标记注册（消除 UnknownMarkWarning）
markers =
    slow: 运行较慢的测试
    smoke: 冒烟测试
    unit: 单元测试
    integration: 集成测试

# 参数默认值
addopts = -v --tb=short
```

常用 `addopts` 示例：

```ini
addopts = -v --tb=short -q --maxfail=10
```

> `--tb=short`：失败回溯只显示简短信息；`--tb=long` 显示完整；`--tb=line` 只显示一行。

## 5.2 覆盖率：pytest-cov

覆盖率 = 被测代码中，有多少比例被测试执行到了。

```powershell
# 运行并输出终端覆盖率报告
py312 -m pytest --cov=math_utils math_utils.py
# 生成 HTML 报告（浏览器打开 htmlcov/index.html）
py312 -m pytest --cov=math_utils --cov-report=html math_utils.py
```

示例输出：

```
Name            Stmts   Miss  Cover
-----------------------------------
math_utils.py      12      1    92%
-----------------------------------
TOTAL              12      1    92%
```

**覆盖率阈值门禁**（低于 80% 直接失败）：

```powershell
py312 -m pytest --cov=math_utils --cov-fail-under=80 math_utils.py
```

> 提示：覆盖率是**参考指标**，不是越高越好。核心逻辑 100% 比无关紧要的代码 100% 更重要。别为了凑覆盖率写"表演性测试"。

## 5.4 mock：pytest-mock（mocker fixture）

测试"调用外部 API / 发邮件 / 读数据库"的代码时，不能真的发请求。用 mock 替换：

```python
# 业务代码
import requests


def fetch_user_name(user_id):
    resp = requests.get(f"https://api.example.com/users/{user_id}")
    data = resp.json()
    return data["name"]
```

```python
# 测试代码（用 pytest-mock 的 mocker fixture）
def test_fetch_user_name(mocker):
    # 用假响应替换 requests.get
    fake_resp = mocker.Mock()
    fake_resp.json.return_value = {"name": "小明", "id": 1}
    mocker.patch("requests.get", return_value=fake_resp)

    name = fetch_user_name(1)
    assert name == "小明"
    requests.get.assert_called_once_with("https://api.example.com/users/1")
```

关键方法：

| 用法 | 作用 |
| --- | --- |
| `mocker.patch("模块.名字", return_value=...)` | 替换函数/方法，指定返回值 |
| `mocker.patch.object(obj, "attr", ...)` | 替换对象属性 |
| `mock.return_value` | 配置"调用一次返回什么" |
| `mock.side_effect` | 配置副作用：抛异常 / 每次不同返回值 |
| `mock.assert_called_once_with(...)` | 断言"被且仅被调用一次，参数正确" |
| `mocker.spy(obj, "method")` | 保留原实现，只记录调用 |

**side_effect 抛异常**：

```python
def test_api_error(mocker):
    mocker.patch("requests.get", side_effect=ConnectionError("网络不通"))
    with pytest.raises(ConnectionError):
        fetch_user_name(1)
```

> 没有 pytest-mock 时，`monkeypatch` 也能做类似的事；`mocker` 的优势：自动清理 + 提供 assert_called 等能力，测试内更方便。

## 5.5 并行：pytest-xdist

用例多时并行加速：

```powershell
py312 -m pytest -n auto          # 自动使用 CPU 核数
py312 -m pytest -n 4             # 用 4 个进程
py312 -m pytest -n auto --dist=loadgroup   # 按 fixture 分组分发
```

**注意**：并行时每个进程独立，session 级共享状态要小心；文件写入类测试用 `tmp_path` 天然隔离，安全。

## 5.6 超时与顺序：pytest-timeout / pytest-ordering

```powershell
# 单个用例超过 10 秒即失败
py312 -m pytest --timeout=10

# 指定某个用例的超时
py312 -m pytest --timeout=30 test_slow.py
```

```python
import pytest


@pytest.mark.run(order=2)
def test_second():
    ...


@pytest.mark.run(order=1)
def test_first():
    ...
```

> 说明：测试本身不应依赖顺序；`order` 仅用于确实需要编排的场景（如冒烟先行）。

## 5.8 规范的测试工程结构

```
my_project/
├── src/
│   └── my_pkg/              # 业务代码
│       ├── __init__.py
│       ├── models.py
│       └── services.py
├── tests/                   # 测试代码（与业务分离）
│   ├── __init__.py
│   ├── conftest.py          # 共享 fixture
│   ├── test_models.py
│   └── test_services.py
├── pytest.ini
└── requirements-dev.txt     # pytest, pytest-cov, pytest-mock, ...
```

运行方式：

```powershell
# 在项目根目录
py312 -m pytest                     # 自动读取 pytest.ini
py312 -m pytest tests/test_models.py -k "login"
py312 -m pytest --cov=my_pkg --cov-report=html
```

## 5.9 常见坑

1. **覆盖率高但测试无效**：断言缺失（只调用不验证）会造成假覆盖率。
2. **mock 打错位置**：要 patch **业务代码里引用它的地方**（如 `my_pkg.services.requests.get`），不是 patch `requests` 本身——取决于代码里怎么 import。
3. **并行 + 共享文件冲突**：并行测试不要写同一个固定路径文件，用 tmp_path。
4. **配置文件找不到**：pytest.ini 必须在**执行 pytest 的目录或其父目录**中才能被发现（rootdir 规则）。
