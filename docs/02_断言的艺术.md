# 第 2 章 断言的艺术

> 本章用时：约 1.5 小时。核心收获：掌握 pytest 的各种断言方式，写出"失败时信息清晰"的测试。

---

## 2.1 基础断言回顾

`assert` 后面跟一个表达式，表达式为假则用例失败。pytest 的断言内省（assertion introspection）会自动展开表达式，显示两边的实际值：

```python
def test_list():
    result = [1, 2, 3, 4]
    assert result == [1, 2, 3, 5]
```

失败输出会自动告诉你 `result` 的实际值，并标记出不同位置（`+ [4], - [5]` 这样的 diff）。

**常见断言写法**：

```python
def test_common_assertions():
    # 字符串
    assert "hello world".startswith("hello")
    assert "abc" in "xxabcxx"
    assert "PYTHON".lower() == "python"

    # 数字
    assert 10 > 5
    assert 10 % 2 == 0

    # 容器
    assert [1, 2] + [3] == [1, 2, 3]
    assert {"k": 1}["k"] == 1
    assert set([1, 1, 2]) == {1, 2}

    # 布尔
    assert []          # 空列表为假
    assert not None    # None 为假
    assert 0 == False  # 注意：0 和 False 相等（值相等）
```

## 2.2 异常断言：pytest.raises

测试"函数应该抛出什么异常"是测试的核心场景之一。

```python
import pytest


def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("除数不能为 0")
    return a / b


def test_divide_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(10, 0)
```

`with pytest.raises(异常类型)`：块内代码**必须**抛出该异常，否则用例失败。

**获取异常对象做进一步断言**：

```python
def test_divide_error_message():
    with pytest.raises(ZeroDivisionError) as exc_info:
        divide(10, 0)
    assert "除数不能为 0" in str(exc_info.value)
```

`exc_info.value` 就是异常实例，`str()` 取到异常信息。

**精确匹配 vs 子类匹配**：`pytest.raises(ZeroDivisionError)` 允许抛出的异常是它的子类（如 `FloatingPointError` 不会，但 `DivisionByZero` 会）。想精确匹配用 `match` 参数：

```python
def test_match_message():
    with pytest.raises(ZeroDivisionError, match="除数"):
        divide(10, 0)   # match 用正则匹配异常信息
```

**一次断言多个异常**：可以用元组 `pytest.raises((ValueError, TypeError))`。

## 2.3 浮点数比较：pytest.approx

浮点运算有精度问题，`0.1 + 0.2 == 0.3` 是 `False`。别直接比较浮点数：

```python
import pytest


def test_float_bad():
    assert 0.1 + 0.2 == 0.3   # 失败！0.30000000000000004


def test_float_good():
    assert 0.1 + 0.2 == pytest.approx(0.3)


def test_float_rel_tol():
    # 指定相对误差 1e-6
    assert 3.14159265 == pytest.approx(3.1415926, rel=1e-6)


def test_float_abs_tol():
    # 指定绝对误差 0.01
    assert 1.005 == pytest.approx(1.0, abs=0.01)
```

`approx` 也支持容器：

```python
def test_approx_list():
    assert [0.1 + 0.2, 0.2 + 0.3] == pytest.approx([0.3, 0.5])
```

## 2.4 警告断言：pytest.warns

测试"代码会发出警告"（比如用了即将废弃的 API）：

```python
import warnings
import pytest


def deprecated_func():
    warnings.warn("这个函数即将废弃", DeprecationWarning)
    return 42


def test_deprecated():
    with pytest.warns(DeprecationWarning):
        deprecated_func()
```

## 2.5 更可读的失败信息：f-string 注释

pytest 支持在断言后用 `# 注释` 形式附加说明（pytest 8+）：

```python
def test_with_note():
    actual = 5
    assert actual == 10  # 期望得到 10，实际是 {actual}
```

失败时输出会带上注释内容，方便排查。

## 2.6 集合断言实用技巧

```python
def test_collection_tips():
    items = ["apple", "banana", "cherry"]

    assert items == ["apple", "banana", "cherry"]   # 顺序敏感
    assert set(items) == {"cherry", "apple", "banana"}  # 顺序不敏感
    assert "banana" in items
    assert len(items) == 3
    assert items.count("apple") == 1
    assert all(len(x) > 3 for x in items)

    data = {"name": "小玉", "age": 18}
    assert data["name"] == "小玉"
    assert "age" in data
    assert {"name": "小玉"} <= data   # 子集判断（字典）
```

**判断"两个列表元素相同但顺序无关"**：转 set 或排序后比较。

## 2.7 断言失败的艺术：只断言一件事

一个测试里塞多个断言不是绝对禁止，但**失败定位会变模糊**。经验法则：

- 一个用例聚焦一个行为；
- 有多个独立断言且彼此无关联时，拆成多个测试函数；
- 相关联的断言（先验前置再验结果）可以放一起。

---

## 2.8 常见坑

1. **拿 `pytest.raises` 当 try/except 用**：它是断言，不是捕获。不抛异常 = 失败。
2. **浮点直接 == 比较**：一律改用 `approx`。
3. **`assert` 报错后信息不够**：可以 `assert 条件, "补充说明文字"`。
4. **异常类写错**：比如函数抛 `KeyError`，你写 `pytest.raises(ValueError)` → 用例失败，这其实是在帮你抓错。
