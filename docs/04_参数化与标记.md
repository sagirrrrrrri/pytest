# 第 4 章 参数化与标记

> 本章用时：约 1.5 小时。核心收获：一份测试逻辑跑多组数据；按需跳过/预期失败；灵活筛选用例。

---

## 4.1 为什么要参数化

写测试最常见的重复：同一个函数，要验证 5 组输入输出。复制 5 个测试函数？太蠢。参数化让**一个测试函数承载多组数据**，每组数据自动成为一个独立用例。

```python
import pytest


def add(a, b):
    return a + b


@pytest.mark.parametrize("a, b, expected", [
    (1, 2, 3),
    (-1, 1, 0),
    (0, 0, 0),
    (100, 200, 300),
    (2.5, 2.5, 5.0),
])
def test_add(a, b, expected):
    assert add(a, b) == expected
```

运行结果：`5 passed`，每个参数组合都是独立用例，单独一个失败不影响其他。

**参数名写法**：字符串 `"a, b, expected"` 中的名字必须与测试函数参数一一对应。

---

## 4.2 ids：给用例起名

默认用例名是 `test_add[1-2-3]`，参数多时看不懂。用 `ids` 自定义：

```python
@pytest.mark.parametrize("a, b, expected", [
    (1, 2, 3),
    (-1, 1, 0),
], ids=["正整数相加", "负数与正数抵消"])
def test_add_named(a, b, expected):
    assert a + b == expected
```

运行 `-v` 会看到 `test_add_named[正整数相加]`。

---

## 4.3 多组参数组合（笛卡尔积）

多个 `parametrize` 装饰器叠加 = 参数的**笛卡尔积**：

```python
@pytest.mark.parametrize("x", [1, 2])
@pytest.mark.parametrize("y", [10, 20])
def test_combine(x, y):
    """会生成 2×2 = 4 个用例：1×10, 1×20, 2×10, 2×20"""
    assert x * y > 0
```

**注意执行顺序**：最后一个装饰器是变化最快的（类似嵌套 for 循环）。

## 4.4 跳过：skip 与 skipif

有些用例在特定条件下不该跑（如只在 Windows 上有效的测试）：

```python
import sys
import pytest


@pytest.mark.skip(reason="功能尚未实现，先跳过")
def test_not_ready():
    ...


@pytest.mark.skipif(sys.platform != "win32", reason="仅 Windows 可用")
def test_windows_only():
    assert sys.platform == "win32"


@pytest.mark.skipif(True, reason="演示：无条件跳过")
def test_demo_skip():
    ...
```

运行输出：`3 skipped`。跳过的用例不算失败。

**条件式跳过**（运行时判断）：

```python
def test_skip_in_runtime():
    if not hasattr(str, "removeprefix"):
        pytest.skip("当前 Python 版本不支持 removeprefix，跳过")
    assert "hello".removeprefix("he") == "llo"
```

## 4.5 预期失败：xfail

代码有已知 bug 或依赖外部条件暂时失败，但不想让整个套件变红——标 xfail：

```python
import pytest


@pytest.mark.xfail(reason="已知问题：暂未实现负数处理")
def test_known_bug():
    assert abs(-5) == -5   # 假如此实现有 bug，则失败


@pytest.mark.xfail(strict=True, reason="严格模式：如果竟然通过了，反而报错")
def test_should_fail():
    ...
```

- 用例失败 → 显示 `xfailed`（预期中的失败，不影响整体通过）；
- 用例竟然通过 → 默认显示 `xpassed`（信息：预期失败却通过，需要关注）；`strict=True` 时直接算失败（提醒你"已知问题修好了，该删 xfail 了"）。

## 4.6 自定义标记与注册

自定义标记用于**分类用例**（如按功能、按优先级）：

```python
import pytest


@pytest.mark.slow        # 自定义标记：慢测试
def test_slow_one():
    ...


@pytest.mark.smoke       # 冒烟测试：核心功能快速验证
def test_smoke_login():
    ...
```

**在 pytest.ini 中注册标记**（避免 PytestUnknownMarkWarning）：

```ini
# pytest.ini
[pytest]
markers =
    slow: 运行较慢的测试
    smoke: 冒烟测试，快速验证核心功能
```

---

## 4.7 按标记筛选：-m

```powershell
py312 -m pytest -m smoke              # 只跑 smoke
py312 -m pytest -m "not slow"         # 排除 slow
py312 -m pytest -m "smoke or slow"    # 并集
py312 -m pytest -m "smoke and not slow"
```

`-k` 按**名字**筛选（`-k "login"`），`-m` 按**标记**筛选，二者可组合。

---

## 4.8 usefixtures：不注入也能用

有些 fixture 只想执行其"准备/清理"副作用，不需要接收返回值：

```python
import pytest


@pytest.fixture
def init_db():
    print("\n[准备] 初始化数据库")
    yield
    print("\n[清理] 关闭数据库")


@pytest.mark.usefixtures("init_db")
def test_uses_db_side_effect():
    assert True   # 不需要用 init_db 的返回值
```

## 4.9 常见坑

1. **参数名写错**（如 `"a,b"` 少空格没关系，但名字拼错）→ 报错提示 fixture 未定义或参数不匹配。
2. **ids 数量与参数组数不一致** → 报错。必须一一对应。
3. **笛卡尔积规模爆炸**：3 个装饰器各 5 组 = 125 个用例，注意控制。
4. **标记未注册** → 有 Warning（不影响运行，但建议注册保持干净）。
5. **xfail 忘记清理**：问题修复后应删除 xfail 标记，否则用例永远"预期失败"。
